# 메트로챗 (가칭)

노선도에서 탑승역·하차역을 선택하고, 실제 타고 있는 열차를 골라 같은 열차를 선택한 이용자와 채팅하는 웹 앱입니다. 현재 **서울시 실시간 역 코드에 포함된 수도권 19개 노선의 일반열차**를 지원합니다. 1·2·5호선 지선, 경의중앙선·경춘선 분기, 6호선 응암 순환을 반영하며 운행 구간을 선택해 같은 노선 안에서 이동합니다. 최소 환승 경로 안내, 구간별 열차 선택, 9호선 급행의 정차역 검증을 지원합니다. 다른 노선 급행·특급·ITX·직통열차는 정차역 검증 자료가 없어 입장을 제한합니다. 공개 URL은 `/metro-chat/`이며 기존 `/bamboo-forest/` 주소는 새 주소로 연결합니다.

## 실행

프로젝트 경로: `/Users/jay/Developer/project-bookey/metro-chat`

Node.js 20 이상. 의존성 설치나 빌드 과정이 없습니다.

```sh
cd /Users/jay/Developer/project-bookey/metro-chat

# 실제 서울시 열차 정보 사용
SEOUL_SUBWAY_API_KEY=발급받은키 npm start
# http://127.0.0.1:3212/metro-chat/

# API 키 없이 화면과 실제 사용자 간 채팅 체험
SUBWAY_DEMO=1 npm start

npm test
```

`SEOUL_SUBWAY_API_KEY`는 서울열린데이터광장에서 발급받은 **지하철 API 인증키**입니다. 키가 없으면 열차 연결 준비 상태를 표시하고 입장을 허용하지 않습니다. `SUBWAY_DEMO=1`은 명시적인 체험 모드로, 화면에 가상 열차임을 표시합니다. 예시 승객이나 자동 생성 채팅은 없습니다. 실제 운영에서는 `SUBWAY_DEMO`를 설정하지 마세요. `.env` 파일을 자동으로 읽지 않으므로 셸 환경변수 또는 서비스 환경 파일로 전달합니다.

다른 브라우저·시크릿 창에서 같은 열차를 고르면 서로 대화할 수 있습니다. 같은 브라우저의 탭은 HttpOnly 세션 쿠키를 공유합니다. 새로고침 후에도 세션이 살아 있으면 선택한 열차에 재접속합니다.

## 동작과 한계

- 서울시 실시간 도착정보의 `subwayId`, `btrainNo`, `updnLine`을 사용합니다. **운행일 + 노선 + 방향 + 열차번호**로 방을 나누므로 탑승역과 하차역이 다른 승객도 같은 열차를 선택하면 연결됩니다. 운행일은 한국 시각 오전 3시에 바뀝니다. 동일 운행일에 열차번호가 재사용되는 경우의 운행 회차 구분은 아직 지원하지 않습니다.
- 실제 탑승 여부를 인증하는 기능은 없습니다. 사용자가 본인의 열차를 직접 선택합니다. API는 승객의 탑승·하차 여부를 제공하지 않습니다.
- 서버가 역별 조회를 20초 캐시하고 동시 요청을 합칩니다. 클라이언트는 열차 선택 화면에서 25초마다 다시 조회합니다. 3분 이상 지난 응답 행은 제외하며, 도착 예정 초는 데이터 생성 시각만큼 보정합니다. 탑승 중에는 별도 실시간 위치 API를 조회해 선택한 열차의 마지막 확인 위치를 노선도에 표시합니다.
- 하차 버튼으로 방을 떠나며, 최대 90분 후 자동 종료됩니다. 자동 하차는 기본 꺼짐이며 사용자가 직접 켠 경우에만 적용합니다. 신선한 위치 정보로 하차역 이전 관측과 이후 도착을 연속 확인해야 종료합니다. 누락·오래된 위치 정보만으로 종료하지 않습니다. 끊긴 세션은 60초간 재접속을 기다립니다.
- 모든 노선에서 선택한 열차의 종착역까지 하차역이 포함되는지 화면과 서버가 검사합니다. 다른 지선으로 가는 열차와 종착역이 하차역에 못 미치는 열차는 입장을 막습니다. 6호선 응암 순환의 단방향 운행, 2호선 순환, 역명 변경 별칭을 처리합니다. API에 없는 종착역·입고 경로는 도달을 보증하지 않고 입장을 거부합니다.
- HTTP + SSE로 접속 인원과 메시지를 전달합니다. 서버가 방 소속과 메시지 길이(300자)·전송 간격을 검증하고, 브라우저는 메시지를 텍스트로 렌더링합니다. POST 요청은 같은 Origin의 JSON만 허용합니다.
- 한 방에 최근 60개 메시지, 최대 1시간 기록을 메모리에 보관합니다. 새로 입장한 이용자는 남아 있는 방 기록을 볼 수 있습니다. 일반 채팅·탑승 상태는 서버 재시작 시 초기화됩니다. 신고·차단·운영 제한은 별도 저장소에 보존하며 계정과 영구 채팅 기록은 없습니다. 최대 100세션이며 다중 서버 동기화와 실제 수용량 부하 검증은 별도입니다.

실제 인증키로 외부 API를 호출해 `INFO-200`(해당 데이터 없음) 응답을 확인했습니다. 운행 중 실제 열차 데이터의 열차번호·방향은 추가 확인이 필요합니다. 테스트에서는 명세에 맞춘 응답을 사용해 파싱·캐시·오류·오래된 데이터 처리를 검증합니다.

## 역별 첫차·막차 안내

선택한 탑승역·방향별로 평일/토요일/휴일 시간표를 사용합니다. 서울시 OA-15492의 공식 공개 표를 서버에서 조회하며, 배포 시점 스냅샷도 포함합니다. 자정 이후의 24~26시 시각은 이전 날짜의 운행으로 계산합니다. 공휴일과 대체공휴일은 한국천문연구원 달력자료의 2026~2027년 목록을 사용하며, 임시공휴일 추가 시 목록 갱신이 필요합니다. 목록이 없는 연도는 운행 종료를 판단하지 않습니다.

시간표상 막차가 지나고 실시간 열차가 없으면 운행 종료 및 다음 첫차를 안내합니다. 실제 도착정보가 있으면 시간표보다 우선해 열차를 표시하며, 실시간 조회 장애와 시간표 미확인 상태는 구분합니다. 시간표는 지연·임시 운행을 반영하지 못할 수 있습니다. 막차 종착역도 표시하지만 선택한 하차역까지의 마지막 도달 가능 열차를 계산하는 기능은 아닙니다.

첫차·막차는 서울교통공사 공개 표의 1~9호선 제공 구간에 적용합니다. 종착역 바깥 방향, 누락된 역/방향, 선택한 운행 구간과 첫차·막차 종착역이 맞지 않는 경우는 미확인으로 처리합니다. 광역철도·경전철·GTX 등 이 표에 없는 노선은 실제 도착정보만 표시하며 시간표를 추정하지 않습니다. 9호선은 공식 시간표 방향 코드가 실시간 도착정보와 반대여서 별도로 매핑합니다. 시간표는 일반/급행 구분 없는 노선 기준입니다.

서버는 노선별로 하루 한 번 시간표를 갱신하고 동시 요청을 합칩니다. 갱신 실패 시 1시간 후 재시도하며, 마지막 정상 자료가 7일을 넘으면 운행 종료를 단정하지 않습니다. 갱신 자료는 메모리에 저장되므로 릴리스 스냅샷을 갱신하려면 `npm run update-timetable`을 실행한 뒤 배포하세요. 공개 표 조회에는 추가 인증키가 필요 없습니다.

## 전체 노선과 역 데이터

지원 노선(19개): 1~9호선, GTX-A, 경의중앙선, 공항철도, 경춘선, 수인분당선, 신분당선, 경강선, 우이신설선, 서해선, 신림선. 인천 1·2호선, 김포골드라인, 용인경전철, 의정부경전철 등 현재 서울시 실시간 역 코드 파일에 없는 노선은 지원 대상으로 표시하지 않습니다. 전국 지하철 지원을 의미하지 않습니다.

- `lines.mjs`: 공식 API ID·역명, 운행 구간·지선·방향 그래프, API 조회용 역명 별칭. 19개 노선의 역 항목 699개와 표시용 운행 구간 28개를 포함합니다. 환승역은 노선별로 중복 집계됩니다.
- `data/network-source.json`: 서울시 OA-12764 최신 첨부 `실시간도착_역정보(20260902).xlsx`의 원본 역 코드와 출처. 4호선 진접·오남·별내별가람은 서울시 진접선 개통 자료에서 보완했습니다.
- `data/first-last.json`: 1~9호선 첫차·막차의 고유 행 2,670건. `npm run update-timetable`로 갱신합니다.

분기 구간은 별도 노선으로 취급하지 않고 원래 노선 ID와 열차번호를 방 키에 사용합니다. 구간 선택이 달라도 같은 열차·방향이면 같은 채팅방입니다. GTX-A는 공식 역 자료의 운정중앙~서울역, 수서~동탄 구간으로 나누며 두 구간 사이를 한 열차로 이동할 수 있다고 표시하지 않습니다. 운영사 직결 운행 변경 시 경로를 갱신해야 합니다.

새 노선의 모든 운행 구간과 채팅은 모의 열차·통합 테스트 및 Chromium에서 검증했습니다. 심야에는 실제 도착정보가 없으므로 모든 노선의 실제 운행 열차번호·방향과 개별 구간의 실시간 제공 범위는 운행 시간대 추가 확인이 필요합니다.

## 환승·운행 중 열차·하차 알림

`journey.mjs`는 일반열차 기준으로 열차 변경 횟수를 먼저, 이후 역 수를 최소화합니다. 신촌/양평의 동명이역은 연결하지 않으며 4호선 총신대입구와 7호선 이수는 환승으로 처리합니다. 같은 노선의 방향 전환이나 2호선 지선 셔틀도 구간을 나눕니다. 실제 운행 여부, 소요시간, 막차 연결을 보장하는 시간표 경로 탐색은 아닙니다. 선택한 경로는 브라우저에 최대 하루 보관하며 수동으로 지울 수 있습니다.

열차 찾기에서 `이미 탑승 중 · 운행 중 열차`를 선택하면 `realtimePosition`의 열차번호·방향·현재 역으로 선택할 수 있습니다. 선택 구간 밖이나 이미 하차역에 도착한 열차는 입장을 거부합니다. 기존 도착정보 조회와 열차 방 식별은 공유합니다. 실제 탑승 여부 인증은 없습니다.

`positions.mjs`는 노선별 위치 조회를 20초 캐시하고 90초 넘게 지난 응답을 제외합니다. 탑승 중 화면은 20초마다 위치를 확인합니다. 자동 하차는 사용자가 직접 켜며, 탑승 시각 이후의 위치가 구간 안에서 순서대로 진행해 하차역 도착 상태를 확인한 경우에만 종료합니다. 첫 위치가 곧바로 하차역이거나 데이터가 끊기면 직접 하차해야 합니다. 브라우저 종료·절전·네트워크 단절에서는 알림을 보장하지 않으며 안내방송을 함께 확인해야 합니다.

9호선 급행은 운영사 공식 16개 정차역을 검증하여 탑승역·하차역 모두 정차할 때 허용합니다. 다른 급행·특급·ITX·직통은 제한합니다. 방향은 종착역으로 물리적 방향을 확정할 수 있으면 이를 우선하고, 순환/분기 등 모호하면 API 방향을 사용합니다. [운영사 정차역 출처](https://www.metro9.co.kr/kor/sub01_04.do).

## 신고·차단 운영

메시지의 신고/차단 버튼과 별도 차단 관리가 있습니다. 차단은 해당 사용자의 화면에서만 메시지를 숨기며 해제할 수 있습니다. 신고는 현재 방의 다른 승객 메시지만 대상으로 하며 10분에 5건, 최대 1,000건을 보관합니다. 동일 메시지 중복 신고는 합칩니다.

신고 메시지·사유와 차단 목록은 30일 기준으로 정리합니다. 시작 시 및 매시간 정리하고 신고/차단 변경 시 저장합니다. 익명 식별 쿠키는 HttpOnly/SameSite/운영 HTTPS Secure 속성과 30일 유효기간을 가지며, 재시작 후 같은 쿠키로 복원한 익명 ID에 차단·전송 제한을 적용합니다. 쿠키 삭제나 다른 기기까지 동일인으로 인증하는 기능은 없습니다.

운영 저장소: `/var/lib/bamboo-forest/moderation.json`. systemd `StateDirectory`로 서비스 사용자 전용 0700 디렉토리를 만들고 파일은 0600으로 원자적 교체합니다. `METRO_STATE_DIR` 미설정 시 개발용 메모리 저장만 사용합니다. 손상된 저장소를 조용히 초기화하지 않고 서버 시작을 실패시킵니다.

관리자 인증은 서버 환경 파일의 `METRO_ADMIN_TOKEN`을 사용하며 일반 브라우저에 전달하지 않습니다. 서버에서 root 권한으로 다음 도구를 실행합니다.

```sh
sudo /opt/mandragora/node/bin/node --env-file=/opt/bamboo-forest/subway.env /opt/bamboo-forest/current/scripts/moderate.mjs list
# list 대신 hide 신고ID / dismiss 신고ID / mute 신고ID 분 을 사용
```

운영자 API: `GET /metro-chat/api/moderation/reports`, `POST /metro-chat/api/moderation/review`. 별도 Bearer 인증이 필요하며 POST는 같은 Origin JSON이어야 합니다. 신고된 메시지 전체 숨김, 신고 기각, 1~1440분 전송 제한을 지원합니다. 운영자 웹 대시보드는 없으며 CLI/API로 처리합니다.

추가 API: `POST trip-check`, `POST trip-options`(`autoLeave` boolean), `POST report`, `POST block`, `POST unblock`. `GET trains`에 `source=arrivals|running`을 지정합니다.


## 3D 객실 화면 (v7)

기존 대나무숲의 전체 화면 3D 공간, 캐릭터 이동, 머리 위 말풍선 방식을 지하철 객실로 옮겼습니다. 탑승 후 바닥 클릭/터치 또는 객실에 포커스를 둔 방향키·WASD로 이동하고, 드래그해서 둘러봅니다. 같은 열차의 연결된 실제 접속자만 캐릭터로 표시합니다. 이동 목적지는 서버가 객실 통로 안으로 제한하고 초당 2.2 단위로 계산해 SSE로 공유합니다. 이동은 `POST /metro-chat/api/move`의 `{ "x": 0, "z": 3 }`으로 요청합니다. 실제 사용자 위치와 관계없는 객실 안 아바타 위치입니다.

말풍선은 최신 발언 하나를 승객마다 20초 동안 표시합니다. 말풍선을 누르거나 오른쪽 위 버튼을 누르면 대화 기록·신고·차단·탑승 정보·하차 설정을 볼 수 있습니다. 기존의 60개/1시간 메시지 보관 정책은 그대로입니다. 탑승 전에는 열차 선택 패널이 열리고, 탑승하면 닫히며 하차하면 다시 열립니다. WebGL을 사용할 수 없으면 패널에서 열차 선택과 텍스트 채팅을 계속 사용할 수 있습니다.

`cabin.js`는 객실/캐릭터/말풍선 렌더링과 조작, `cabin.css`는 전체 화면과 패널 배치를 담당합니다. `vendor/three.module.min.js`는 Three.js 0.160.1의 로컬 사본이며 MIT 라이선스는 `vendor/three.LICENSE`에 포함합니다. 외부 CDN이나 빌드 없이 동작합니다. 배포 아카이브에는 이 세 항목과 `vendor` 디렉토리도 포함해야 합니다.


## 가상 열차 확장 (v7)

- 6개의 가상 객실을 연결했습니다. 연결문 클릭/통로 끝까지 걷기, 아래 편성도, 이전/다음 버튼 또는 객실에 포커스를 둔 Q/E로 이동합니다. 실제 열차의 칸 수나 탑승 위치를 의미하지 않습니다. 열차 방과 하차역·자동 하차 설정은 칸 이동 중에도 유지됩니다. 칸마다 좌석 색, 대화 주제, 광고가 다릅니다.
- 같은 칸의 접속자만 3D로 표시하고, 편성도에는 열차 전체의 칸별 접속 인원을 표시합니다. 기본 채팅 범위는 열차 전체입니다. 입력창에서 ‘같은 칸’을 고르면 그 칸의 사람에게만 전송합니다. 칸을 옮기면 그 칸에 남아 있는 최근 메시지를 볼 수 있습니다. 20초 말풍선·최근 60개/1시간 기록 정책은 유지합니다.
- 좌석 클릭 또는 좌석 메뉴로 앉기/일어서기를 선택합니다. 동일 열차·동일 칸의 같은 좌석은 서버에서 중복 착석을 막습니다. 이동·칸 변경·하차 시 좌석을 해제합니다. 화면의 착석은 가상 동작이며 실제 좌석 예약이 아닙니다.
- 손 인사·공감·응원은 4초 동안 같은 칸의 다른 승객에게 보입니다. 2.5초 간격 제한과 운영자의 전송 제한을 적용합니다. 차단한 승객의 캐릭터·반응·말풍선은 표시하지 않습니다. 옷 색상 5종도 다른 사용자에게 공유합니다.
- 가상 브랜드 광고 6종을 객실 포스터와 상단 패널에 표시합니다. 18초마다 교체하며, 포스터 클릭이나 객실 설정의 ‘광고 둘러보기’로 크게 볼 수 있습니다. 실광고·추적·결제·외부 광고 요청은 없습니다. 광고 소재는 `cabin-data.mjs`의 `ADS`에서 관리합니다.
- 창밖 풍경은 터널/한강의 저녁을 고를 수 있습니다. 실제 운행 위치와 무관한 가상 배경입니다. 열차 소리는 사용자가 직접 켠 경우에만 합성 재생하며, 숨겨진 탭에서는 일시 정지합니다. 애니메이션 끄기와 배터리 절약 화질을 제공합니다. 풍경·움직임·화질 설정은 브라우저에 저장하며, 소리는 자동 재생하지 않습니다.

추가 API (익명 세션·동일 Origin JSON): `POST car` (`car`: 1~6), `POST seat` (`seat`: 좌석 ID 또는 null), `POST emote` (`kind`: wave/heart/clap), `POST appearance` (`coat`: 0~4). `POST say`는 선택적으로 `scope: train|car`를 받습니다. 응답/SSE는 `cars`(칸별 인원), `players`의 `car`·`seat`·`coat`·`emote`, 메시지의 `car`·`scope`를 포함합니다. 이동 API는 200ms, 칸 이동은 600ms, 좌석 변경은 300ms, 반응은 2.5초 간격을 제한합니다. 상태는 단일 서버 메모리이며 일반 세션과 함께 재시작 시 초기화됩니다.

렌더링은 현재 칸 한 개를 재사용하므로 칸 수에 비례해 3D 자원이 늘어나지 않습니다. 이동만 갱신되는 SSE에서는 노선도·환승 UI를 다시 만들지 않습니다. 서버의 칸 이동·좌석 경쟁·채팅 범위·반응 만료·외형 동기화·하차 제한을 통합 테스트합니다.
